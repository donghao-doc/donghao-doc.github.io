# 生命周期

## 小程序运行机制

| 概念  | 含义                           |
|-----|------------------------------|
| 冷启动 | 首次打开，或小程序被销毁后再次打开，需要重新加载并初始化 |
| 热启动 | 小程序还未被销毁，从后台重新进入前台           |
| 挂起  | 暂停小程序 JS 线程执行，内存状态保留         |
| 销毁  | 完全终止小程序运行，再次打开需要冷启动          |

常见的状态变化：

```text
冷启动 → 前台 → 后台 → 挂起 → 销毁
          ↑      │      │
          └──────┴──────┘  未销毁时再次打开：热启动
```

:::tip
- 点击右上角胶囊中的关闭按钮、将微信切到手机后台或锁屏，都是把小程序切到后台，而不是关闭/销毁小程序。
- 进入后台约 **5 秒**后会挂起；挂起后约 **30 分钟**未回到前台，就会被销毁。但后台音乐播放、后台地理位置等能力可让小程序在后台持续运行，不进入挂起状态。
- 系统资源紧张时也可能提前回收，所以 30 分钟内再次打开也不一定是热启动。
:::

## 小程序更新机制

微信会缓存小程序代码包。开发者发布新版本后，用户当前打开的仍可能是旧版本。

| 更新方式    | 发生时机                        | 当前使用的版本                  |
|---------|-----------------------------|--------------------------|
| 启动时同步更新 | 微信会定期检查小程序是否有更新，或长时间未使用的小程序 | 先更新，再打开新版本；若更新失败，启动本地旧版本 |
| 启动时异步更新 | 每次冷启动时异步检查并下载新版本            | 本次启动使用本地旧版本，下次冷启动时使用新版本  |

### 提示用户重启更新

使用 `wx.getUpdateManager()` 获取更新管理器。在 `app.js` 的 `onLaunch` 中注册监听，新版本下载完成后提示用户是否重启。

```js
const updateManager = wx.getUpdateManager()

// 收到检查更新结果
updateManager.onCheckForUpdate(result => {
  // hasUpdate 表示是否存在新版本
  console.log('是否有新版本', result.hasUpdate)
})

// 新版本下载成功
updateManager.onUpdateReady(() => {
  // 提示用户是否重启
  wx.showModal({
    title: '更新提示',
    content: '新版本已准备好，是否重启应用？',
    success(result) {
      if (result.confirm) {
        // 应用新版本并重启小程序
        updateManager.applyUpdate()
      }
    },
  })
})

// 新版本下载失败
updateManager.onUpdateFailed(() => {
  console.log('新版本下载失败，稍后重试')
})
```

:::tip
- 开发者工具可在编译模式中勾选“下次编译时模拟更新”进行调试。
- 正常情况下，发布新版本 24 小时后可覆盖 99% 以上的用户。
:::

## 生命周期

小程序的生命周期包含三个层次：应用生命周期、页面生命周期、组件生命周期。

### 应用生命周期

`App()` 用于注册小程序，必须在 `app.js` 中调用，且只能调用一次。

| 钩子函数       | 触发时机          |
|------------|---------------|
| `onLaunch` | 小程序初始化完成      |
| `onShow`   | 小程序启动或从后台进入前台 |
| `onHide`   | 小程序从前台进入后台    |

执行流程：

- 冷启动：`onLaunch → onShow`。
- 切后台：`onHide`。
- 未销毁时再次进入前台：`onShow`。
- 销毁后再次打开：`onLaunch → onShow`。

### 页面生命周期

| 钩子函数              | 触发时机             |
|-------------------|------------------|
| `onLoad(options)` | 页面加载             |
| `onShow`          | 页面显示或后台切前台       |
| `onReady`         | 页面首次渲染完成         |
| `onHide`          | 页面被隐藏，如打开新页面或切后台 |
| `onUnload`        | 页面被卸载、销毁         |

执行流程：

- 页面初次打开：`onLoad → onShow → onReady`。
- 页面切前台/切后台（显示/隐藏）：`onShow`、`onHide`。

:::tip
- 同一个页面实例的 `onLoad`、`onReady` 只执行一次。
- `onLoad(options)` 可接收路由参数。
:::

### 页面切换的生命周期

假设从 A 页面跳转到 B 页面：

| 操作                               | A 页面                  | B 页面                                |
|----------------------------------|-----------------------|-------------------------------------|
| `navigate` 跳转                    | 保留实例，执行 `onHide`      | 创建实例，执行 `onLoad → onShow → onReady` |
| `redirect` 跳转                    | 销毁，执行 `onUnload`      | 创建实例，执行首次加载流程                       |
| 从 B 返回 A                         | A 重新显示，执行 `onShow`    | B 销毁，执行 `onUnload`                  |
| 从 tabBar 页面 A 切换到另一个 tabBar 页面 B | A 隐藏，执行 `onHide`，不会销毁 | 首次进入执行首次加载流程，已创建过则只触发 `onShow`      |
